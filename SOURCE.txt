官方安装包的对应源码
GitHub Actions 的同一次构建在 Windows 安装包之外同时上传 DshDeck-Source-<version>-<commit>.zip，commit 为该次构建的完整 Git 提交。源码 ZIP 只包含该提交已跟踪的程序源码、必要配置、构建脚本与许可证材料；没有用户数据、密钥、截图、第三方宠物素材或本机测试/文档。
源码 ZIP 与安装包在同一次构建页提供等价下载入口。仓库同一提交也可使用 https://github.com/Misaka009982/DshDeck/archive/<commit>.zip 获取。分发者应在安装包可获取期间持续提供对应源码，而不是只依赖会到期的 Actions Artifacts。
应用界面不再提供“许可与源码”板块或菜单；完整许可与来源文件位于源码根目录／安装目录，版本与对应提交通过同一次构建页、源码 ZIP 文件名和公开项目核对。本文件不声称开发者未提交的本地修改已在公开仓库出现；自行分发修改版时必须一起提供该修改版的对应源码。

生成与修改
1. 使用 Windows x64、PowerShell 7、Node.js 24.10.0 或满足 package.json engines 的版本。
2. 在解包源码根目录，根据 package.json 准备依赖：npm install。
3. 用户主动执行 npm run package:win，脚本用 tsconfig.release.json 编译生产源码、tools/build-renderer.mjs 生成本地页面 bundle，再按 electron-builder.json 生成 NSIS 安装包。
4. 预期产物 release/DshDeck-Setup-<version>-x64.exe；将自己的源码改动一并提供即可安装、运行修改版。没有特别的秘密密钥、签名门槛、设备锁或服务器认证材料作为修改版的安装条件。
5. 普通本地构建/运行入口是 npm run build 与 npm start；程序不会自动安装依赖或下载宠物素材。实际服务器访问仍遵循其正常登录与权限规则，这不构成安装修改版本的限制。
